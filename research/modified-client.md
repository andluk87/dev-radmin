# Копия клиента с собственным RSA-ключом

`research/client_key.py` создаёт офлайн-копию `RvControlSvc.exe` с собственным
публичным ключом RSA 1536/65537. Меняются только 212 байт блока публичного ключа
и PE checksum. Проверки SRP, сообщений и подписей в коде не отключаются.
Подпись изготовителя изменённого EXE становится недействительной.

`windows/Start-RadminLabClient.ps1` готовит отдельный каталог из такой копии и
исходных локальных DLL пользователя. Python на Windows для подготовки не нужен:
нужны уже созданный изменённый EXE и его JSON-отчёт. Скрипт сверяет хеши всех
исходных файлов, хеш изменённого EXE и независимо сравнивает байты EXE; любые
изменения вне фиксированного блока ключа и checksum отвергаются.

## Подготовить каталог без запуска

```powershell
powershell -NoProfile -File .\windows\Start-RadminLabClient.ps1 `
  -PatchedServicePath .\RvControlSvc-own-key-research.exe `
  -PatchReportPath .\client-key-copy.json
```

При нестандартной установке добавьте `-InstallationDirectory 'D:\Radmin VPN'`.
Выходной каталог должен быть новым и находиться вне исходной установки.
В каталог копируются `RvControlSvc.exe`, `RvROLClient.dll`, `shelper.dll` и
`RvUESClient.dll`, `libcurl.dll`, `libssl-3.dll`, `libcrypto-3.dll` и `vcruntime140.dll`. Скрипт не устанавливает службу, не меняет реестр и не запускает
EXE без отдельного параметра запуска. Исходные DLL и EXE не входят в репозиторий.

## Почему отдельная папка не изолирует клиент

У исходного EXE обнаружен режим `/run` — «Run as application»; `/service`
предназначен только для Service Manager. Строка `/run` находится по VA `0x51c66c`,
её использование — `0x441801`, описание режима — `0x51c678` / `0x441831`.
Это статическое подтверждение наличия режима, не результат запуска на Windows.

Даже при `/run` код использует общие ресурсы установленного клиента:

- HKLM Registry32 `SOFTWARE\Famatech\RadminVPN\1.0`;
- именованный канал `\\.\pipe\RadminVpnGuiChannel` (`0x519e74`, ссылка `0x40f052`);
- событие `Global\RadminVPN_{916CB59C-7D6C-4A14-B96A-C16EE96591A8}_evt`;
- устройство драйвера `\\.\RVPNNETMP`.

Поэтому новая папка или другое имя службы не дают отдельного профиля. Запуск
копии способен затронуть регистрацию, сети и адаптер данного Windows-компьютера.
Для запуска нужна отдельная тестовая Windows/VM со снимком состояния, без рабочих
учётных данных и сетей. Заменять установленную службу на основном компьютере
этой процедурой не следует.

## Запуск на отдельной тестовой Windows

Сначала вне этого скрипта подготовьте тестовую систему: исходная служба уже
остановлена, GUI закрыт, `ServerAddress` указывает на собственный стенд.
Откройте PowerShell от имени администратора: нативный клиент запрашивает
доступ к своим настройкам HKLM с правами записи, даже когда адрес уже задан.
Формат адреса и перенаправление ещё не проверены реальным запуском; скрипт
только сравнивает имеющееся значение, не подставляет адрес и не переносит
регистрацию. Команда ниже создаёт новый каталог и вызывает `/run`:

```powershell
powershell -NoProfile -File .\windows\Start-RadminLabClient.ps1 `
  -PatchedServicePath .\RvControlSvc-own-key-research.exe `
  -PatchReportPath .\client-key-copy.json `
  -RunOnDedicatedTestMachine -ExpectedServerAddress '<адрес своего стенда>'
```

Скрипт откажет при работающей исходной службе, процессе службы/GUI или
несовпадении адреса. Он не останавливает службу, не меняет настройки доверия,
не отключает проверки Windows и не запускает процесс от SYSTEM. Права процесса
наследуются от PowerShell; скрипт проверяет запуск с правами администратора.
Если Windows блокирует изменённый EXE, это результат проверки; обход блокировки
не предусмотрен. Драйвер остаётся исходным подписанным драйвером пользователя.

После запуска скрипт ждёт две секунды и сообщает, остался ли процесс жив,
либо выводит код завершения. Эти данные, признак повышения прав и только
значение DWORD `PowerOn` сохраняются в `lab-client-launch.json`.
Отсутствующее `PowerOn` не означает выключение: нативный клиент использует
значение по умолчанию 1. Скрипт не меняет его и не читает регистрационные секреты.
Запуск процесса сам по себе не подтверждает подключение к серверу или готовность VPN.
Собственный сервер должен иметь
соответствующий приватный RSA-ключ и подходящую SRP-запись; протокол регистрации,
полное управление сетями и передача VPN-трафика ещё не реализованы.

## Настройка адреса и откат

`windows/Set-RadminLabAddress.ps1` допускает IPv4/hostname без порта и меняет
только Registry32/ServerAddress. До записи он создаёт новый JSON-backup значения;
существующий backup не перезаписывается. При `-Restore` возвращает прежнее значение
или удаляет только ServerAddress, если его прежде не было. Скрипт требует
`-DedicatedTestMachine`, остановленной исходной службы и отсутствия её/GUI-процессов.
Пример для PowerShell администратора на отдельной Windows:

```powershell
powershell -NoProfile -File .\windows\Set-RadminLabAddress.ps1 -ServerAddress '192.0.2.10' -BackupPath .\server-address-backup.json -DedicatedTestMachine
# Откат после остановки тестовой копии:
powershell -NoProfile -File .\windows\Set-RadminLabAddress.ps1 -Restore -BackupPath .\server-address-backup.json -DedicatedTestMachine
```

Замените 192.0.2.10 адресом своего сервера. Настройка адреса не переносит
учётные данные и не решает ещё не реализованную первичную регистрацию.
