# Проверка исходной DLL на Windows

Добавлен самостоятельный `bin/native-check-windows-386.exe`. Он вызывает исходную
32-битную `shelper.dll` версии 2.1.4951.1 с проверенным SHA-256 и проверяет её
взаимодействие с Go-реализацией в одном процессе. Серверный RSA-ключ, соль и все
учётные данные синтетические. Подключения к серверу нет: проверка не требует Docker
на Windows, установленного Git или доступа к облачному стенду.

Программа собрана для Windows x86, проверена кросс-компиляцией и `go vet`.
**На настоящей Windows она ещё не запускалась.** Следующий необходимый результат —
отчёт с тестового компьютера пользователя; без него работоспособность Windows ABI
и загрузки DLL не заявляется. Математика обмена и смена ключа отдельно подтверждены
исходной DLL в Linux-эмуляторе.

## Запустить

В обычном PowerShell, права администратора не требуются:

```powershell
Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/andluk87/dev-radmin/main/windows/Run-RadminNativeCheck.ps1' -OutFile .\Run-RadminNativeCheck.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Run-RadminNativeCheck.ps1
```

`ExecutionPolicy Bypass` действует только в запущенном процессе PowerShell,
постоянная политика не меняется. Скрипт найдёт DLL в стандартном каталоге Radmin VPN,
скачает собственный EXE и его SHA-256 с GitHub, проверит обе контрольные суммы и
создаст новый каталог `radmin-native-check-<дата>`.

Если Radmin установлен в другом месте:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Run-RadminNativeCheck.ps1 -DllPath 'D:\Radmin VPN\shelper.dll'
```

Прислать нужно только `native-check.json` из созданного каталога. Он содержит
статусы тестов, версию схемы, платформу и фиксированный хеш DLL. В отчёте нет
реального аккаунта, пароля, ключей, IP-адресов или захвата трафика. Ошибки DLL/API
записываются без содержимого буферов. При блокировке запуска Windows или несовпадении
версии DLL понадобится текст ошибки; настройки защитных проверок скрипт не меняет.

## Что проверяет EXE

1. Загрузка неизменённой DLL и её `SHelper_Init`, версия протокола 3.
2. Native RSession-клиент → Go RSA-декодер на собственном случайном ключе 1536 бит.
3. Совпадение 64-байтового ключевого материала у сторон.
4. Native CChannel ↔ Go CChannel, исходный SRP-клиент DLL ↔ Go SRP-сервер.
5. Успешный пароль, неверный пароль, изменённый M1, повреждённая шифрованная запись.
6. В успешном сценарии — совпадение 40-байтовых ключей SRP и смена ключей AES
   без сброса IV, затем двусторонняя передача синтетических данных.

Программа не создаёт VPN, не перезапускает службу, не меняет реестр/адаптеры
и не заменяет файлы Radmin. Внешние команды управления VPN пока не реализованы.
Ключи/синтетические пароли не передаются через командную строку и не попадают в JSON.

Бинарник использует x86 Windows ABI; Go-буферы закрепляются на время native-вызовов,
выходные буферы копируются через Windows API и освобождаются через DLL.
На Linux `scripts/build.sh` собирает этот EXE с `GOOS=windows GOARCH=386 CGO_ENABLED=0`.
Ни DLL, ни исходный EXE изготовителя в Git не распространяются.
