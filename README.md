# Исследование собственного сервера для Radmin VPN

Сейчас подготовлены статический анализ клиента, офлайн-разбор реального ETL,
чтение/запись TCP-рамок, диагностический TCP/UDP-сервис в Docker и скрипты для Windows.
Совместимый VPN-сервер пока не реализован. Изменённый клиент
не выпускался. Контейнер **не создаёт VPN-сети, не авторизует клиентов и не пересылает трафик**.

Результаты и точные адреса функций: [research/findings.md](research/findings.md).
Исходные EXE/DLL и установщик в репозиторий не включаются.

## Скачать с GitHub и запустить

На Windows с установленным Git:

```powershell
git clone https://github.com/andluk87/dev-radmin.git
cd dev-radmin
powershell -NoProfile -File .\windows\Get-RadminDiagnostics.ps1
```

На Linux amd64 с установленными Git, Docker и Docker Compose v2:

```bash
git clone https://github.com/andluk87/dev-radmin.git
cd dev-radmin
bash scripts/start.sh
```

В Git включён собранный `bin/probe` и его SHA-256. `start.sh` проверяет checksum,
собирает локальный контейнер без скачивания базового образа и ждёт healthcheck.
Go для этого запуска не нужен. Это запуск диагностического стенда;
совместимый Radmin VPN-сервер пока не реализован.
Для обновления выполните `git pull --ff-only`, затем повторите `bash scripts/start.sh`.

## Проверка на Windows

Скопируйте `windows/Get-RadminDiagnostics.ps1` на тестовый Windows-компьютер.
Оставьте Radmin VPN запущенным и выполните из каталога скрипта:

```powershell
powershell -NoProfile -File .\Get-RadminDiagnostics.ps1
```

Скрипт в течение 30 секунд собирает версии и SHA-256 основных модулей, состояние
службы, выбранные значения реестра и её TCP/UDP-адреса. Он не меняет настройки,
не перезапускает службу, не экспортирует регистрацию/пароли и не захватывает пакеты.
Если часть сведений недоступна обычному пользователю, запустите PowerShell от администратора.
Результат — `radmin-diagnostics-<дата>/diagnostics.json`.
В отчёте остаются IP-адреса соединений.

Для следующего этапа нужен этот отчёт: он позволит сопоставить установленную версию
с извлечёнными файлами и выбрать адреса/порты для записи начального обмена.
Формат `ServerAddress`, фактическое перенаправление и SRP-обмен ещё не проверены на Windows.
Не меняйте реестр по одному лишь наличию строк в бинарнике.

## Записать начальный обмен на Windows

Диагностика тестового ПК подтвердила совпадение пяти модулей с исследованным
установщиком, действительные по мнению Windows подписи, `Registry32/ServerAddress`
типа String и управляющее TCP-соединение на порт 17301. Первый реальный ETL уже
получен и разобран: [результаты](research/capture-findings.md). Повторять захват
для текущего разбора не требуется; инструкции ниже остаются для будущих тестов.

Откройте **PowerShell от администратора**, перейдите в клонированный репозиторий:

```powershell
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows\Capture-RadminControl.ps1 -RestartService
```

Политика запуска изменяется только для этого дочернего процесса PowerShell.
`-RestartService` один раз перезапустит Radmin VPN, кратковременно разорвав его
соединения. Запись начинается до перезапуска, длится 20 секунд и ограничена 16 МБ.
Скрипт читает текущий ServerAddress, но не меняет реестр и настройки VPN.
Встроенный netsh явно ограничивает Ethernet-тип IPv4, протокол TCP и адрес
управляющего сервера; TCP/17301
будет выделен при разборе. Другие адреса из отчёта не включаются в фильтр.
Существующая trace-сессия не останавливается перед запуском: при ошибке старта
скрипт завершится. Останавливается только успешно запущенная этим скриптом запись.

Для преобразования ETL в PCAPNG скрипт скачивает официальный Microsoft etl2pcapng
v1.11.0 в папку результата, сверяет фиксированный SHA-256 и только затем запускает.
Если скачивание/конвертация не удались, исходный ETL сохраняется; его тоже можно
передать для анализа. `-SkipConversion` позволяет вообще не скачивать конвертер.
Исходная версия выполнялась на Windows и создала пригодный ETL, но ошибочно
отклонила его после ненулевого stop. Исправлены обработка stop и Ethernet-фильтр;
эти изменения ещё не проверены запуском на Windows.

Результат: `radmin-capture-*/radmin-control.pcapng` (либо `.etl`) и
`capture-metadata.json`. Передавайте их отдельно для анализа, **не коммитьте в Git**:
там есть адреса и содержимое пакетов, возможно идентификаторы клиента.

## Диагностический контейнер

Нужны компилятор Go 1.22+, Docker Engine и Docker Compose v2 на Linux amd64.
Имя `go` в системе может принадлежать другой программе: сначала проверьте `go version`.
При необходимости укажите компилятор через `GO_BINARY`.

```bash
bash scripts/build.sh
docker compose -p dev-radmin-research up -d
python3 scripts/smoke_probe.py
docker compose -p dev-radmin-research logs probe
docker compose -p dev-radmin-research down
```

`scripts/build.sh` запускает тесты, собирает статический Linux-бинарник и Docker-образ
на базе `scratch`. Сборка образа и сервис не требуют выхода в Интернет: в образ
не входят проприетарные DLL, установщик, Wine, VPN-клиенты или инструменты сборки.
Контейнер работает без root, дополнительных capabilities и записи в свою файловую систему.
Логи ограничены двумя файлами по 10 МБ.

Порты по умолчанию: `127.0.0.1:4899` TCP/UDP. **4899 — выбранный порт стенда,
а не установленный анализом стандартный порт Radmin VPN.** Публикация только на
loopback намеренная: Windows на другой машине к нему не подключится. При переносе
на свой тестовый сервер выберите его конкретный адрес через `BIND_ADDRESS`, порт
через `PROBE_PORT`, и ограничьте доступ адресом своего Windows-компьютера в firewall.
Доступ к VPS и внешний адрес сервера в этой сессии не предоставлены.

На каждое TCP-соединение записываются максимум первые 64 байта за 3 секунды,
затем соединение закрывается. Для UDP записываются первые 64 байта датаграммы.
JSON содержит hex, SHA-256 наблюдавшихся байтов, транспорт и адрес отправителя.
Логи настоящего клиента могут содержать идентификаторы; храните их локально до разбора.
Никаких протокольных ответов, регистраций или обещания успешного VPN-соединения нет.

Проверка контейнера: `docker compose -p dev-radmin-research exec -T probe /probe -healthcheck`.
Внутренний `/healthz` сообщает `vpn_ready: false`.

Если домашний каталог Docker CLI доступен только для чтения, используйте отдельный
доступный для записи каталог `DOCKER_CONFIG` для локальной сборки этого образа.
Не переносите туда токены вручную. При работе с внешними registry сохраняйте настройки
аутентификации, прокси и доверенных CA вашей среды.

## Повторение статического анализа

```bash
python3 -m venv .venv
.venv/bin/pip install -r research/requirements.txt
.venv/bin/python research/analyze_pe.py /путь/к/извлечённым/файлам --output /tmp/evidence.json
```

Инструмент ничего не запускает: читает PE-структуры, считает хеши, находит импорты,
экспорты, ссылки на выбранные строки и RTTI/vtable протокольных классов.
`research/evidence.json` содержит результат для присланного установщика.

## Офлайн-разбор ETL

```bash
.venv/bin/pip install -r research/capture-requirements.txt
.venv/bin/python research/analyze_etl.py /путь/radmin-control.etl \
  --metadata /путь/capture-metadata.json --output /tmp/control-summary.json \
  --pcap /tmp/control-only.pcap
.venv/bin/python -m unittest discover -s research -p test_analyze_etl.py -v
```

IP берётся из локальных метаданных, в JSON-результат адреса и тела сообщений
не попадают. PCAP содержит выбранный реальный трафик — храните его вне Git.
Первое сообщение `00000004 03000000` и BE-префиксы длины подтверждены двумя
новыми соединениями. Go-пакет `internal/wire` умеет читать/писать такие рамки,
но не реализует аутентификацию или расшифровку последующих сообщений.

## Облачная рабочая среда

Используйте существующий checkout `/workspace/dev-radmin`. Задача уже изолирована;
создавать Git worktree для этих шагов не требуется. Исследуемые бинарники и локальные
инструменты сохранены отдельно в `/workspace/radmin-analysis`.
Запущенные контейнеры нужно запускать заново после восстановления среды.
