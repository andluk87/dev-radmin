# Серверный контейнер для клиентского архива

Этот каталог запускает протокольный сервер на TCP/17301. Старый
`../scripts/start.sh` запускает отдельный диагностический probe на 4899.

Требуются Linux amd64, Docker с Compose v2 и OpenSSL. Go для запуска не нужен:
в `../bin/srp-lab` включён статический бинарник, его SHA-256 проверяется скриптом.

Из корня клонированного репозитория:

```bash
git pull --ff-only
cd server
bash setup.sh
BIND_ADDRESS=0.0.0.0 LAB_ENDPOINT=192.0.2.10 bash start.sh
```

`setup.sh` попросит passphrase для `paired-key.encrypted.pem`. Она передаётся
владельцу отдельно в чате и не включается в Git. Файл использует стандартное
шифрование PKCS#8; OpenSSL расшифровывает его только локально. После расшифровки
скрипт сверяет отпечаток публичного ключа с клиентским архивом, создаёт
`config/` с правами 0700 и секретные файлы с правами 0600. Повторный запуск
не меняет уже существующую согласованную конфигурацию; несовпадающую не перезаписывает.
`config/` исключён из Git и Docker build context.

192.0.2.10 в примере — документационный адрес. Замените его адресом своего
сервера, доступным с Windows. Разрешите входящий TCP/17301 в
используемом firewall/VPS. В `docker ps` ожидается `0.0.0.0:17301->17301/tcp`.

```bash
docker logs --tail 100 radmin-own-key-control-1
# Остановка из server/:
docker compose -p radmin-own-key down
```

Для обновления уже настроенного контейнера выполните `git pull --ff-only`
из корня репозитория и снова запустите `start.sh` с теми же переменными.
Повторно расшифровывать ключ не требуется.

Журнал содержит время UTC и `connection_id`. Пустое TCP-подключение
(`Test-NetConnection`) завершается событием `connection_closed` с
`stage=version_frame`, `error_kind=eof`; это не проверка протокола Radmin.
`bootstrap_complete` означает успешный RSA-обмен. При `rejected/bootstrap`
поля `stage` и `error_kind` показывают этап отказа; `rsa_decode` означает,
что сервер получил RSA-блок нужной длины, но не принял его. Событие
`listening` также содержит SHA-256 публичного ключа для сверки с клиентом.
Содержимое сообщений и ключи в этот журнал не записываются.

Пара соответствует клиентскому ZIP с SHA-256
`18c18b8fffe8416543b3c2adf55fc35511882d096324e92c1b69d9591c28c343`.
Серверный публичный ключ имеет SPKI SHA-256
`91486e028cacf48843b8a0d556346957e67071169ef71cdf8944de6d852ea48e`.

## Границы готовности

Это всё ещё прототип, не полный VPN. Реализованы RSA/SRP, смена ключа,
нативно принимаемый LoginComplete75 и один IsAlive; после него экспериментальное
соединение закрывается. Нет первичной регистрации реального Windows-профиля,
сетевых операций, NAT/relay и передачи VPN-пакетов. `vpn_ready` остаётся false.

Публичный `demo-record.json` содержит только синтетическую исследовательскую
запись user42, полученную для уже опубликованного в тестах fixture-пароля.
Обычный облачный профиль Radmin VPN автоматически с этой записью не совпадает:
даже после открытия TCP-порта возможен ожидаемый отказ на SRP. Локальные
регистрационные данные Windows не извлекаются и проверки аутентификации не отключаются.
